# CFGTOOL -- проверка, форматирование, сравнение, чтение и правка файлов конфигурации

Работает с файлами конфигурации в синтаксисе libconfig через
библиотеку yaLIBCFG: проверяет файл, пишет его в каноническом виде,
сравнивает два файла, читает настройку, меняет или удаляет её на
месте - комментарии и оформление файла сохраняются.

Формат:

```
CFGTOOL команда параметры [/квалификаторы]
```

Команды: CHECK, FORMAT, DIFF, GET, SET, DELETE и HELP. Команду и
квалификатор можно сокращать, пока сокращение однозначно;
квалификатор можно писать и в длинной форме Unix -- --NOCASE вместо
/NOCASE.

Сообщения идут в стандартный поток ошибок, данные -- значение,
листинг, текст -- в стандартный вывод. Код завершения для оболочки:
0 -- успех (у DIFF: различий нет), 1 -- DIFF нашёл различия, 2 --
ошибка.

## Пути -- как называется настройка

Путь ведёт от верха файла к настройке:

```
system.hostname         настройка HOSTNAME группы SYSTEM
vlans.[1]               элемент 1 (с нуля) списка или массива
ports.[id=9].mtu        в списке PORTS - элемент, у которого ID равен 9
ports.[name="up 1"]     строковый ключ - в двойных кавычках
```

Вместо точки можно писать косую черту: system/hostname. Путь со
скобками или пробелами заключайте в кавычки от оболочки.

Аргумент -- не длиннее 255 октетов. Значение или путь, которые
начинаются с / или --, будут приняты за квалификатор: заключите их в
двойные кавычки внутри кавычек оболочки:

```
$ cfgtool set router.cfg system.logdir '"/var/log"'
```

## CHECK -- проверить файл

```
CFGTOOL CHECK файл [/FINGERPRINT /NOCASE /NOINCLUDE]
```

Разбирает файл и включаемые им файлы. О правильном файле сообщает с
числом настроек и отпечатком; каждую ошибку -- с файлом, строкой и
столбцом.

```
$ cfgtool check router.cfg
%CFG-S-CORRECT, router.cfg is correct: 16 settings, UUID a0f0b155-8348-5765-97a7-4dfb5164faba
```

### /FINGERPRINT

Пишет в стандартный вывод только отпечаток -- для сценария.
Отпечаток -- это UUID, вычисленный по настройкам: у двух файлов с
одинаковыми настройками он один и тот же, какими бы ни были их
комментарии и оформление.

### /NOCASE

Имена настроек сравниваются без учёта регистра.

### /NOINCLUDE

Директива @include считается ошибкой.

## FORMAT -- записать в каноническом виде

```
CFGTOOL FORMAT файл [/OUTPUT=файл /NOCASE /NOINCLUDE]
```

Пишет настройки файла в каноническом оформлении: по настройке на
строку, группы -- в несколько строк с отступом в табуляцию,
настройки включаемых файлов -- на месте строк @include.

Комментарии НЕ сохраняются: это текст одних настроек. Годится, чтобы
сравнить два файла как тексты или придать файлу чистый вид.

### /OUTPUT=файл

Пишет в файл, а не в стандартный вывод.

## DIFF -- сравнить две конфигурации

```
CFGTOOL DIFF старый-файл новый-файл [/OUTPUT=файл /POSITIONAL /NOTIME /NOCASE]
```

Сравнивает настройки двух файлов -- не текст: комментарии,
оформление и порядок настроек в группе не учитываются -- и пишет
листинг в духе утилиты DIFFERENCES, каждое различие со строкой в
каждом из файлов. Элементы списка сопоставляются по ключу (id, name
или key), если он есть.

Код завершения -- 1, если различия есть.

### /POSITIONAL

Элементы списков сопоставляются только по положению.

### /NOTIME

Листинг без времени: одно и то же сравнение даёт один и тот же текст
при каждом запуске.

### /OUTPUT=файл

Пишет листинг в файл.

## GET -- прочитать настройку

```
CFGTOOL GET файл путь [/FLAT /NOCASE]
```

Пишет значение настройки в стандартный вывод: строку -- как есть (без
кавычек), остальные значения -- как в файле, группу или список -- в
несколько строк.

```
$ cfgtool get router.cfg ports.[id=9].mtu
9216
```

### /FLAT

Группа или список -- в одну строку.

## SET -- изменить настройку

```
CFGTOOL SET файл путь значение [/TYPE=ключевое-слово /OUTPUT=файл /LOG /NOCASE]
```

Задаёт значение и записывает файл обратно на место: меняется только
значение, комментарии и оформление остаются. Отсутствующая настройка
создаётся вместе с группами на её пути.

```
$ cfgtool set router.cfg ports.[id=9].mtu 1500
$ cfgtool set router.cfg system.location "Lab, rack 4"
```

### /TYPE=ключевое-слово

AUTO (по умолчанию) берёт тип из текста, как в файле: 1500 -- целое,
0x1F -- шестнадцатеричное целое, 12L -- 64-битное, 1.5 --
вещественное, true -- логическое, "текст" -- строка. Всё, что не
является ровно одним таким значением -- 10.0.0.5, 12abc, 12 # note,
-- становится строкой как есть. Уже существующая настройка сохраняет
свой тип: строка берёт текст как есть, вещественное принимает целое.
STRING всегда задаёт текст как строку.

### /OUTPUT=файл

Пишет изменённый главный файл в другой файл; исходный остаётся.
Отказ, если изменение попадает во включаемый файл: там оно
потерялось бы.

### /LOG

Сообщает об изменении.

## DELETE -- удалить настройку

```
CFGTOOL DELETE файл путь [/OUTPUT=файл /LOG /NOCASE]
```

Удаляет настройку вместе со строками комментария над ней и
записывает файл обратно на место.

## HELP -- краткая справка по командам

```
CFGTOOL HELP
CFGTOOL команда /HELP
```

## Messages -- что сообщает утилита

### CORRECT

Файл правильный; далее -- число настроек и отпечаток.

### SYNTAX, UNTERM, BADNUM, BADESC, DUPNAME, MIXARRAY

Ошибка в тексте файла, с позицией. Смотрите указанную строку -- и
строку перед ней: пропущенные ; или } проявляются строкой позже.

### OPENIN, READERR

Файл не читается; errno говорит почему (2 -- нет такого файла, 13 --
нет доступа).

### NOSETTING

GET или DELETE ничего не нашли по пути. Проверьте путь командой
CFGTOOL GET файл на его родителе.

### CANTSET

SET или DELETE отказали; следующее сообщение говорит почему: TYPE --
настройка другого типа, BADNAME -- недопустимое имя, NOTFOUND -- на
пути нет элемента (элементы не создаются).

### DIFFERENT, IDENTICAL

Что нашёл DIFF.

### INCMODIFIED

SET или DELETE с /OUTPUT изменили настройку включаемого файла, а её
нельзя записать в другой файл. Пишите на место, без /OUTPUT.

### ARGLONG

Аргумент длиннее 255 октетов.

### WRITERR, OPENOUT

Файл не записывается: нет места (errno 28), нет доступа (13).
Исходный файл остаётся как был.
